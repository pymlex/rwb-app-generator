# Corporate documentation

Retrieve the relevant corporate template and system-analysis rules for the current document.
Document actual code and contracts, distinguish assumptions, and retain source FR identifiers.
System analysis covers scope, roles, scenarios, FR and NFR criteria, data, API, events and errors.
API descriptions include exact fields and bounds, authorisation, examples, errors and transactions.
Architecture describes deployable components, data relationships, state transitions and editable UML.
ADRs record context, alternatives, decision, consequences, accountable team and approval status.
The service guide covers operation, real health and metrics, backup, recovery and dependency failures.
Host restart is an operator action. Do not invent an unauthenticated restart endpoint.
Mark inapplicable template sections with their reason instead of inventing components.
Report build, test, security, token and attempt evidence separately from generated implementation claims.
Attribute team ownership and use the project's GPL-3.0 footer. Do not invent stakeholder approvals.
