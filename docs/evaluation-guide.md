# Руководство для жюри: что сделано, где смотреть, как проверить

Документ — карта доказательств по критериям оценки. Он не заменяет [чек-лист из 48 пунктов](requirements-compliance.md) и не содержит результатов прогона. Результаты конкретного прогона собираются в `docs/evidence/<run-id>/README.md` после первого полного прогона на VM; до тех пор такого каталога нет.

Описано состояние на ревизию `03e0951` (ветка `codex/pipeline-quality-gates`), дата — 31.10.2026. Пути вида `generator/…` относятся к репозиторию пайплайна, пути вида `runs/parking/…` — к проекту, который пайплайн сгенерировал для кейса 1.

## 2. Критерии оценки

Группировка составлена по этапам задания (анализ, документация, backend, frontend, тестирование и безопасность, инфраструктура, эффективность) и по названиям критериев в плане работ. Баллы в репозитории зафиксированы только для двух блоков: «анализ — 20» и «документация — 10» ([план работ](workplan.md), раздел 8). Для остальных блоков баллы и точные формулировки нужно взять из свода организаторов — в репозитории их нет.

Статус показывает, что есть в коде. Слова «работает» без свидетельства прогона здесь нет: где прогона не было, это сказано.

Регламент организаторов подмешивается из локального индекса SQLite FTS5 (5 источников, у каждого фрагмента — SHA-256 исходного файла). Статус: код и тесты есть, результата на реальном брифе пока нет | Репозиторий: [models.py](../generator/models.py) (`Analysis`, `Requirement`, `Question`, `Blueprint`), [analysis.md](../generator/prompts/analysis.md), [architecture.md](../generator/prompts/architecture.md), `Pipeline.analyst` и `Pipeline.architect` в [pipeline.py](../generator/pipeline.py), [knowledge.py](../generator/knowledge.py), [knowledge/sources](../knowledge/sources). ## 3. Что искать в сгенерированном проекте

Каталог проекта (`runs/<имя>`) собирается из фиксированных шаблонов и файлов, которые пишет модель. Ниже — расположение свидетельств.

| Путь | Что там |
| --- | --- |
| `requirements.md`, `.pipeline/input.sha256` | исходный бриф и его SHA-256 |
| `docs/analysis.json`, `docs/blueprint.json` | структурированные требования и контракт API |
| `docs/clarifications.json`, `docs/clarification-answers.json` | блокирующие вопросы и данные ответы |
| `docs/system-analysis.md`, `architecture.md`, `api.md`, `user-guide.md`, `development.md`, `limitations.md`, `README.md` | документация проекта |
| `backend/`, `frontend/`, `tests/` | код приложения и приёмочные тесты |
| `docker-compose.yml`, `.gitlab-ci.yml`, `scripts/configure.py` | развёртывание и CI |
| `reports/checks.json` и `reports/<проверка>.json` | результаты всех проверок `verify` и журналы запущенных проверок |
| `reports/summary.json`, `reports/verification.md` | итоговый статус, токены, вызовы, время |
| `reports/traceability.json`, `requirement-tests.json`, `requirement-review.json` | требование → файлы → тесты → ревью утверждений |
| `reports/backend-review.json`, `reports/contract-check.json` | ревью backend и проверка контракта |
| `reports/security.json` | отчёт Trivy |
| `.pipeline/events.jsonl`, `.pipeline/artifact-manifest.json` | журнал событий и манифест файлов с привязкой к требованиям |
| `.pipeline/checkpoints/`, `.pipeline/responses/`, `.pipeline/agent-tools/` | кэш этапов, ответы модели, обращения ролей к инструментам |

Журнал `.pipeline/events.jsonl`, `checkpoints` и `responses` исключены из Git сгенерированного проекта (его `.gitignore`), поэтому в опубликованный репозиторий они не попадают; в `docs/evidence/<run-id>/` будут приложены извлечения без ключей.

## 4. Что пока не доказано

- Ни одного полного прогона на VM: генерация кейса 1, `verify --execute --deploy`, девять шагов демонстрации, перезапуск без дублей начальных данных (задачи R-02, R-03).
- Второй домен (`examples/inventory.md`) пока не прогонялся (R-04).
- Статический анализ (A-02), отчёты в Markdown (D-01), сводка метрик (D-02), публикация в GitLab (D-04) — задачи плана, в этой ревизии их нет.
- Личности водителей и проверка владельца записей ограничены общим токеном роли (A-06); подробности — в [security.md](security.md).
- Нативный клиент Kotlin не делается: принят PWA ([ADR-005](architecture.md)).

Перечень задач и сроки — в [workplan.md](workplan.md). Когда у прогона появятся свидетельства, пункты чек-листа в [requirements-compliance.md](requirements-compliance.md) получат ссылки на `docs/evidence/<run-id>/`.
